Gyllir handbook

Gyllir is the build system and package manager for GNU-Ymir projects — what cargo is to Rust, or dub to D. It compiles .yr sources into executables and libraries, resolves dependencies, runs unit tests, generates documentation and publishes versions to a registry.

Gyllir does not compile anything itself: it drives the gyc compiler, decides what needs recompiling, and links the result. One file — gyllir.toml — describes the whole package.

Installing

Gyllir needs a working gyc toolchain on the machine — it is looked up on PATH under the name given by the compiler key of the manifest, which defaults to gyc:

gyc --version

Gyllir itself ships as a Debian package. Grab the latest one from the releases page and install it:

sudo apt-get install ./gyllir_<version>_amd64.deb

The package installs the gyllir binary to /usr/bin/, the static assets used by the documentation generator to /etc/gyllir/res/, and a bash completion script to /etc/bash_completion.d/. Check the install with:

gyllir --version

which prints the version of Gyllir followed by the version of the compiler it found.

Hello world

mkdir hello && cd hello
gyllir init          # answers a handful of questions, writes gyllir.toml
gyllir run           # builds ./hello, then runs it

That is the whole loop. Your first project walks through what each of those steps created and what to do next.

What Gyllir does for you

  • Builds a package into an executable or a static library, in debug or release mode, with an incremental cache under .target/.
  • Resolves dependencies declared as local paths or git remotes, checks out the version matching a filter, and builds them recursively before your package.
  • Runs unit tests written as __test blocks, compiled into a separate test binary.
  • Generates documentation as a static HTML site from the doc comments in your sources.
  • Publishes versions: bumps the version, commits, tags, and pushes to a local directory or a git registry.

Conventions in this handbook

Shell blocks are commands you type; TOML blocks are fragments of gyllir.toml. Paths like src/main.yr are relative to the package directory — the directory holding gyllir.toml, which is where every Gyllir command must be run.
