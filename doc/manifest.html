The manifest: gyllir.toml

One TOML file describes the package: who it is, what it produces, what it needs, and where it is published.

name = "myapp"
license = "GPL-v3"
description = "An example package"
version = "0.1.0"
authors = ["Jane Doe <jane@example.com>"]
compiler = "gyc"
type = "executable"
libraries = ["m"]
flags = ["-Wall"]

[registry]
git = "git@github.com:jane/myapp.git"

[dependencies.somelib]
version = ">=1.2.0"
url = "git:https://github.com/example/somelib"

[commands]
set-version = { cmd = "./tools/set-version.sh", post = false }

Package identity

KeyTypeRequiredDescription
namestringyesName of the package. Also the name of its single target, and therefore of the artifact it produces, when it declares no [targets.*] table.
licensestringyesFree-form license string, e.g. "GPL-v3".
descriptionstringyesOne line describing the package.
versionstringyesVersion of the package, "major.minor.patch". Rewritten by gyllir publish.
registrystring or tableyesWhere gyllir publish pushes versions. See URLs.
authorsarray of stringsnoThe authors of the package.
compilerstringnoThe compiler binary Gyllir drives, looked up on PATH. Defaults to "gyc".

What the package produces

These keys describe a single artifact. A package that declares [targets.*] tables must not use them at the top level — see the exclusivity rule below.

KeyTypeDefaultDescription
type"executable" or "library""executable"An executable is linked into ./<name>; a library is archived into ./lib<name>.a.
package-rootstring—Root module of the sources, relative to src/ and without the .yr extension. Without it, an executable roots at src/main.yr and a library at src/__lib__.yr. A declared root that does not exist is an error, never a fallback.
test-rootstring—Root module of the unit tests, relative to test/. Defaults to test/__test__.yr.
testsbooleantrueSet to false to opt the package out of unit testing. It then cannot declare test-root.
librariesarray of strings[]C libraries to link, each passed as -l<name>.
flagsarray of strings[]Raw options appended to every compiler invocation, last — so they override the ones Gyllir picked (-g, -O3, …).

Single artifact, or targets — never both

A package produces one artifact described by the keys above, or several described by [targets.<name>] tables. Writing type, package-root, test-root, tests, flags or libraries at the top level of a package that also declares a target table is rejected with an explicit error rather than silently ignored — a target inherits nothing, so those keys would simply go unread.

The keys that stay at the top level in a multi-target package are the ones that say nothing about what is produced: the identity of the package (name, version, license, description, registry, authors, compiler) and what it needs to be built ([dependencies], [commands]).

URLs

Both registry and a dependency's url take the same form. Either a prefixed string:

registry = "local:/home/jane/.local/gyllir/myapp"
registry = "git:git@github.com:jane/myapp.git"

or a table with a single local or git key, which is what Gyllir writes when it rewrites the file itself:

[registry]
git = "git@github.com:jane/myapp.git"

A bare string with neither prefix is read as a git remote.

[dependencies]

One [dependencies.<name>] table per dependency, each declaring a version filter and a url. The Dependencies page covers them in full.

[dependencies.midgard]
version = ">=1.0.0"
url = "git:git@github.com:GNU-Ymir/midgard.git"

[targets]

One [targets.<name>] table per artifact, for packages that build more than one. See Targets.

[commands]

Custom command lines run around each target build. One [commands.<name>] table per command:

[commands]
set-version = { cmd = "./tools/set-version.sh", post = false }
strip       = { cmd = "strip myapp", post = true, cwd = "." }
KeyTypeDefaultDescription
cmdstringrequiredThe command line to run. It is split on spaces and executed directly — this is not a shell, so pipes, globs and quoting do not apply. Put anything more involved in a script.
postbooleanfalsefalse runs the command before the build, true after it.
cwdstring"."Directory the command runs from. A relative path is resolved against the package directory.

Commands belong to the package, not to a target: in a multi-target package each command runs once per target being built. A command that exits non-zero aborts the build, and the error names the [commands.<name>] table it came from.

Watch the post value. It must be a real boolean (or the strings "true" / "false"). Anything else is refused rather than being read as a pre-build command, which would run it at the wrong moment.

Error messages

Gyllir validates the whole manifest before doing any work, and every message names the entry to fix — for example '[targets.cli]', 'type' is invalid: "app" is not a build type, expecting one of "executable", "library". A file that is not even valid TOML is reported with the line and column the parser choked on.
