Command reference

Every sub-command, its flags, and what it produces. All commands run in the package directory — the one holding gyllir.toml.

Global options

OptionEffect
-h, --helpPrint the usage of Gyllir, or of a sub-command when given after its name.
-V, --versionPrint the version of Gyllir, followed by the version of the compiler it drives.

Running gyllir with no sub-command prints the usage and exits with a failure.

The [target] argument

build, test, doc and run accept the name of a target as an optional first argument. A package that declares no [targets.*] table has exactly one target, named after the package itself, so you can ignore this until you need several artifacts.

gyllir build              # every target of the package
gyllir build mylib        # only the target named "mylib"

Naming a target the package does not declare is an error, and the message lists the ones it does.

gyllir init

gyllir init

Interactively creates a package in the current directory: writes gyllir.toml, src/ with a root module, test/__test__.yr, a .gitignore, then runs git init and commits. It refuses to run if a gyllir.toml already exists. See Your first project for the questions it asks.

gyllir build

gyllir build [target] [--release] [--locked] [--offline] [-j N] [-v]
FlagEffect
--releaseCompile with -O3 instead of -g, into the release cache.
--lockedFail instead of writing a new gyllir.lock. The CI flag: it turns a dependency that would move into an error.
--offlineResolve without any network access — no clone, no fetch. Implies --locked.
-j NNumber of compilation threads. Defaults to the number of processors.
-v, --verbosePrint every command line Gyllir runs, and pass -fv to the compiler.

Resolves and builds dependencies first, then the targets, in an order where a target is always built after the targets it links. Produces ./<output> for an executable target and ./lib<output>.a for a library target.

gyllir run

gyllir run [target] [-- args...]
gyllir run [target] [args...]

Builds the target (always in debug mode) and executes its binary from the package directory. Everything after the target name is forwarded to your program untouched; use -- when the first argument might otherwise be read as a target name, or starts with a dash.

The exit code of Gyllir is the exit code of your program, or 128 + signal if a signal killed it.

With several targets declared, gyllir run needs a target name — it will not guess. Running a library target is an error.

gyllir test

gyllir test [target] [--release] [--dry] [--locked] [--offline] [-j N] [-v]
FlagEffect
--dryCompile the test binary but do not run it.
--releaseCompile the tests with -O3.
--locked / --offlineAs for gyllir build.
-j NNumber of compilation threads.
-v, --verboseVerbose mode.

Compiles the target together with its test/ tree and links ./<output>.test. Without a target name it tests every target that has not opted out with tests = false, running the binaries one after the other; the exit code is that of the first one that failed. Naming a target that opted out is an error, and so is running gyllir test on a package where no target is testable.

gyllir clean

gyllir clean [--doc] [-a|--all]
FormRemoves
gyllir clean.target/, and the artifacts of every target (./<output> or ./lib<output>.a, and ./<output>.test).
gyllir clean --docOnly the __doc/ directory.
gyllir clean --allAll of the above, plus .deps/ — cleaning local dependencies recursively before removing the directory.

gyllir doc

gyllir doc [target] [-o outputDir] [-i input.doc.json] [--locked] [--offline] [-v]
FlagEffect
-o, --outputDirectory to write the site into. Defaults to __doc/.
--locked / --offlineAs for gyllir build.
-i, --inputRender a .doc.json file produced by an earlier run instead of recompiling the sources.
-v, --verboseVerbose mode.

Compiles the sources for documentation only (no linking), then renders a static HTML site. For a package with several targets, each target gets its own sub-directory: __doc/<target>/. The intermediate .doc.json is kept in the build cache at .target/<target>/doc/<output>.doc.json, which is what -i expects.

gyllir doc serve

gyllir doc serve [target] [-o outputDir] [--host address] [-p port]
FlagEffect
-o, --outputDirectory to serve. Defaults to __doc/, and to __doc/<target>/ when a target is named.
--hostAddress to listen on. Defaults to 127.0.0.1.
-p, --portPort to listen on. Defaults to 8000.

Regenerates the documentation (same work as gyllir doc) and then serves it over HTTP until it is killed. Beyond the pages themselves, the server answers symbol queries on /symbol, which is what makes the search box of a served page cover the whole site: a page opened straight from the __doc/ directory only searches the module it documents, since nothing is there to answer for the others.

POST /symbol

The body is a json object with a required query and an optional type restricting the results to one kind of symbol. The same query can be passed as url parameters of a GET, which is handier from a shell:

curl -X POST -d '{"query": "buildTargets"}' http://127.0.0.1:8000/symbol
curl 'http://127.0.0.1:8000/symbol?query=buildTargets&type=fn'
{
   "results" : [{
             "kind" : "fn",
             "module" : "gyllir::repo::manager",
             "name" : "GyllirManager.buildTargets",
             "url" : "gyllir_repo_manager.html"
   }],
   "total" : 1
}

Names are matched case insensitively, exact matches first, then prefixes, then substrings, and each result is qualified inside the page documenting it (Class.method). total counts every match, which is more than the number of results returned when a query matches more symbols than one answer carries. type takes the kind written in the pages themselves — fn, ctor, class, record, entity, trait, enum, def, macro, let, module — and accepts function/method for fn and global/field for let. A request naming no symbol is answered with a 400.

The index is built once at startup, from the .doc.json of the target being served, so a source change is picked up by restarting the server.

gyllir update

gyllir update [--std] [dependency...] [-v]

Resolves the dependency graph again and rewrites gyllir.lock, without compiling anything. Naming no dependency (and passing no --std) updates every entry; naming some updates only those, leaving the rest pinned where they are. A transitive dependency can be named too, even though no gyllir.toml of yours declares it.

The std lib resolved by [std] is never named positionally — it would be ambiguous with an actual dependency a package could otherwise declare under that same name — so --std updates it instead:

gyllir update             # every dependency moves to the newest version its filter accepts
gyllir update somelib     # only "somelib" moves
gyllir update --std       # only the std lib resolved by [std] moves

This is the only command that bumps a locked version: every other one honors the lock file and only writes it for dependencies it does not yet pin.

gyllir publish

gyllir publish <message> [--major|--minor|--patch] [--dry] [-y]
FlagEffect
<message>Required. The commit message of the published version.
--major / --minor / --patchWhich component to bump. Mutually exclusive; a patch bump is the default.
--drySkip the verification build and test run before publishing.
-y, --yesDo not ask for confirmation.

Builds and tests the package, bumps version in gyllir.toml, commits, tags the commit v<version>, and pushes to the configured registry.
