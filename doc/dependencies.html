Dependencies

Other Gyllir packages your package builds against, fetched from a git remote or a local path and built before yours.

Declaring one

One [dependencies.<name>] table per dependency. The name is yours to choose — it is the directory the dependency is resolved into, and the name targets use to select it.

[dependencies.somelib]
version = ">=1.2.0"
url = "git:https://github.com/example/somelib"

[dependencies.midgard]
version = "*"
url = "local:/home/jane/ymir/midgard"
KeyTypeRequiredDescription
versionstring or arrayyesThe version filter deciding which version is checked out.
urlstring or tableyesWhere to get it: git:<remote> or local:<path>, see URLs.
link-targetsarray of stringsnoWhich of the dependency's library targets to link. Omit to link all of them; it cannot be empty.

Version filters

FilterSelects
"*"Any version — the highest one available.
"1.2.0"Exactly that version.
">=1.2.0"The highest version at least 1.2.0. >, < and <= work the same way.
[">=1.2.0", "<2.0.0"]An array is a conjunction: every filter must pass.
"master"A name — a branch or a non-numbered tag — matched literally.

Versions come from the git tags of the dependency, and a tag may be written either 1.2.0 or v1.2.0. Among the tags that pass the filter, the highest one wins. Comparators only make sense against a numbered version: ">=master" is rejected when the manifest is read.

When no version matches, the error lists the versions the dependency actually offers, so you can see whether the filter or the remote is at fault.

How resolution works

On every build, for each dependency, Gyllir:

  1. Places it under .deps/<name> — a local: dependency becomes a symlink to the given path (recreated each time), a git: one is cloned there the first time and reused afterwards.
  2. Picks a version: if the branch currently checked out already passes the filter, it is kept as is — that is what makes local, in-progress dependencies usable. Otherwise the tags are fetched and the matching version is checked out.
  3. Reads the dependency's own gyllir.toml and resolves its dependencies, recursively.
  4. Builds its library targets, and puts their root modules on your include path and their archives on your link line.

A dependency is checked out by version, so even a local: one has to be a git repository. If it is not, the error says so explicitly.

What gets linked

Only the library targets of a dependency are of any use to you: an executable it also declares is never linked into your package. A dependency that declares no library target at all is an error.

By default every library target of the dependency is linked. link-targets narrows that down:

[dependencies.toolkit]
version = ">=2.0.0"
url = "git:git@github.com:example/toolkit.git"
link-targets = ["core"]        # ignore the other libraries it ships

Naming a target the dependency does not declare, or one that is an executable, is an error that lists what it does declare.

On your side, each target selects which dependencies it links — and remember that a declared target links exactly the ones it lists.

Cycles

A dependency graph that comes back to a package already being resolved is rejected with a RecursiveDependency error naming the chain. The same applies to targets linking each other inside one package.

Keeping the tree clean

gyllir clean --all        # removes .deps/ as well as the build outputs

.deps/ is in the .gitignore that gyllir init writes, and should stay untracked: it is entirely reconstructible from the manifest.

Example: a library and its user

In ~/ymir/mylib/gyllir.toml:

name = "mylib"
license = "MIT"
description = "A small library"
version = "1.0.0"
type = "library"

[registry]
local = "/home/jane/.local/gyllir/mylib"
cd ~/ymir/mylib
gyllir build              # produces libmylib.a
git tag v1.0.0            # versions come from tags

In the package that uses it:

[dependencies.mylib]
version = ">=1.0.0"
url = "local:/home/jane/ymir/mylib"
gyllir build              # resolves .deps/mylib, builds it, then builds this package

Your sources then use the modules of mylib as if they were part of the project.
