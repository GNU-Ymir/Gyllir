Your first project

Create a package, build it, run it, test it, document it — and understand every file that appears along the way.

1. Create the package

gyllir init creates a package in the current directory, so make one first. It refuses to run if a gyllir.toml is already there.

mkdir hello && cd hello
gyllir init

It asks a handful of questions, each with a default in brackets that you accept by pressing enter:

QuestionDefaultMeaning
NamemainPackage name, and the name of the artifact it produces.
Author nameyour git user.nameFirst entry of authors.
DescriptionA minimal Ymir appOne line describing the package.
LicenseproprietaryFree-form license string.
Type (executable/library)executableWhat the package produces.
Registrylocal:$HOME/.local/gyllir/<name>Where gyllir publish pushes versions.

2. What it created

hello/
├── gyllir.toml        the manifest: everything Gyllir knows about the package
├── .gitignore         ignores .deps/, .target/, __doc/ and the produced artifacts
├── src/
│   └── main.yr        root module of an executable (__lib__.yr for a library)
└── test/
    └── __test__.yr    root module of the unit tests

gyllir init also runs git init and makes an initial commit — Gyllir leans on git for versioning, so a package is expected to be a git repository.

The generated gyllir.toml looks like this:

name = "hello"
license = "MIT"
description = "A minimal Ymir app"
compiler = "gyc"
type = "executable"
version = "0.1.0"
authors = ["Jane Doe"]
libraries = []

[dependencies]

[commands]

[registry]
local = "/home/jane/.local/gyllir/hello"

Every key is described in the manifest reference.

3. Build it

gyllir build              # debug build (-g)
gyllir build --release    # release build (-O3)

An executable package produces ./hello in the package directory; a library package produces ./libhello.a. Intermediate results live under .target/ — see How a build works.

Where does the root module come from? A package that declares no [targets.*] table roots an executable at src/main.yr and a library at src/__lib__.yr. Name another file with package-root if you need to. Every other .yr file under src/ is compiled too, but must be reachable from the root module — Gyllir warns about any module that is not attached to the package tree.

4. Run it

gyllir run                # builds, then runs ./hello
gyllir run -- --flag x    # everything after -- is forwarded to your program

gyllir run always rebuilds first, in debug mode. It exits with the exit code of your program (or 128 + signal if a signal killed it), so it composes with shell scripts and CI.

5. Write and run tests

Unit tests live under test/, rooted at test/__test__.yr, and are written as __test blocks. A test fails by throwing — typically through assert:

use std::io;

__test {
    println("Example of first test");

    // To make a test fail, throw an exception
    // for example, assert(false);
}
gyllir test               # compile ./hello.test and run it
gyllir test --dry         # only compile it, do not run

The test binary is ./hello.test, next to the normal artifact. The test tree is compiled against your sources, so test/ modules can use the modules of src/ directly. --dry is what CI uses when it wants to run the binary itself with extra options, e.g. coverage.

6. Generate the documentation

gyllir doc                # writes the HTML site into __doc/
gyllir doc -o site        # ... into site/ instead

The generator reads the /** ... */ doc comments of your sources and renders a static site. Nothing is linked during a doc build, so it works even on a package whose dependencies you have not built.

7. Clean up

gyllir clean              # remove .target/ and the produced artifacts
gyllir clean --doc        # remove __doc/
gyllir clean --all        # remove all of the above, plus resolved dependencies (.deps/)

Turning it into a library

Set type to "library", rename the root module to src/__lib__.yr, and the next build produces ./libhello.a instead of an executable. Other packages can then depend on it — see Dependencies. A package that needs to ship both a library and a CLI in one repository declares two targets.
