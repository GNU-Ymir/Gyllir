Targets

A target is one artifact — an executable or a static library — built from one source tree. A package builds as many as it declares.

Every package has targets

A package that declares no [targets.*] table still has exactly one target, synthesized from its top-level keys and named after the package. So gyllir build on a plain package builds one target called myapp, producing ./myapp. You do not have to think about targets until you want a second artifact.

To build several, declare them explicitly. Each [targets.<name>] table is self-contained: a target inherits nothing from the package, which is why declaring a target table forbids the artifact keys at the top level.

name = "myapp"
license = "MIT"
description = "A library and the CLI that uses it"
version = "0.1.0"

[registry]
git = "git@github.com:jane/myapp.git"

[targets.mylib]
type = "library"

[targets.cli]
type = "executable"
targets = ["mylib"]
output = "myapp"

This builds ./libmylib.a and ./myapp, in that order.

The root module of a declared target

A declared target roots at <source-dir>/<name>.yr — the file named after the target — unless it declares package-root. It does not fall back to main.yr or __lib__.yr; only the target synthesized for a package that declares none does that.

[targets.cli]
source-dir = "src/cli"     # sources under src/cli/
package-root = "main"      # rooted at src/cli/main.yr

Two targets can share one source-dir as long as they root at different modules, or each can have its own directory. Every .yr file under a target's source-dir is compiled for that target, so separate directories are usually what you want when the two artifacts have little in common.

A package-root naming a file that does not exist is an error, and the message names both the module Gyllir looked for and the key that decides where it looks.

Linking targets together

targets = [...] lists the targets of the same package this one links against. The listed targets are built first — their root modules go on the include path and their archives on the link line — and this holds transitively.

[targets.core]
type = "library"

[targets.plugins]
type = "library"
targets = ["core"]

[targets.cli]
targets = ["core", "plugins"]

Gyllir orders the build itself, so the declaration order in the file does not matter. A target that links itself, links a target the package does not declare, or takes part in a cycle is rejected before anything is compiled. Building or testing one target automatically builds the targets it links, even when the command names only that one target.

Selecting dependencies per target

Dependencies are declared once for the whole package, and each target picks the ones it needs:

[dependencies.midgard]
version = "*"
url = "git:git@github.com:GNU-Ymir/midgard.git"

[dependencies.somelib]
version = ">=1.0.0"
url = "git:https://github.com/example/somelib"

[targets.mylib]
type = "library"
dependencies = ["midgard"]

[targets.cli]
targets = ["mylib"]
dependencies = ["midgard", "somelib"]

A declared target links exactly what it lists. Omitting dependencies — or writing an empty array — links no dependency at all, not all of them. The single target synthesized for a package that declares no target table has no such list to write, so it keeps linking everything the package declares.

A target that links another target does not automatically inherit its dependency selection at the manifest level, but it does get everything that target already put on the link line, so the artifacts still resolve.

C sources

A target can compile C files and fold them into its artifact — for a library, they are archived into the produced lib<output>.a; for an executable, they go on its link line.

[targets.mylib]
type = "library"
c-sources = ["c/glue.c", "c/vendor/*.c", "c/deep/**/*.c"]
c-flags = ["-Ic/include", "-DWITH_GLUE=1"]

Each entry is one of three forms, all relative to the package directory:

FormMatches
c/glue.cA literal path.
c/vendor/*.cEvery .c file directly in c/vendor/, not in its sub-directories.
c/deep/**/*.cEvery .c file under c/deep/, recursively.

Object files land in .target/<target>/<kind>/c-objs/ and are recompiled only when the source is newer than the object. They are compiled with the same compiler binary as the Ymir sources, with -g or -O3 to match the build mode, and c-flags appended last.

Working with several targets

gyllir build              # every target, in dependency order
gyllir build cli          # cli, and the targets it links
gyllir test               # tests every target that did not opt out
gyllir test mylib         # tests only mylib
gyllir run cli -- --help  # runs the cli target, forwards --help
gyllir doc                # one site per target, under __doc/<target>/

gyllir run is the one command that needs a target name whenever the package declares more than one — it will not pick for you.
